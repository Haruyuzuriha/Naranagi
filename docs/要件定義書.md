## 2. プロジェクト概要 {: #overview }

PDF上に自由に描画・書き込みができ、読書中に同一ウィンドウ内でノートを取れる、語学学習者向けのPDFビューワーアプリケーションである。単なる注釈ツールではなく、注釈・ノート・AIによる文脈検索・個人辞書が一つの基盤モデルを共有し、互いに連携して動作する「オールインワン」の読書・学習環境を目指す。

### 2.1 プロジェクトの位置付け

語学学習者が電子書籍・PDF教材を読みながら、単語や表現を「一つの知識ファイル」としてアーカイブできる学習支援ツールと位置づける。単なるPDFビューワーではなく、注釈・ノート・AIルックアップ・個人辞書が共通の基盤モデルを共有して連携する統合環境とする。

### 2.2 スコープ

#### 対象

* PDF上への自由な描画・書き込み(F-01)
* 同一ウィンドウ内での文章ベースのノート機能(F-02)
* テキストブックマークとノートのシームレスな紐付け(F-03)
* AIルックアップ(語彙・専門用語・語源に限定したAI検索)(F-04)
* 本を横断した個人辞書のアーカイブ機能(F-05)

#### 対象外

* モバイルアプリ版
* Webブラウザ版
* NotebookLM的なチャット型AI(自由対話型の要約・QA機能)
* 図表(グラフ・マインドマップ等)のみに依存したノート機能
* ビジネス化・収益化
* OCR対応・スキャンされた画像ベースPDFへの対応

## 3. 背景・目的 {: #background-purpose }

### 3.1 背景

電子書籍を読みながらノートを取る際、複数のウィンドウ(PDFビューワー、ノートアプリ、辞書、検索エンジン)を行き来する必要があり、時間がかかるという課題が自分自身の学習体験として頻繁に発生していた。

### 3.2 解決したい問題

複数ウィンドウ間の往復コストにより、読書と学習ノート作成の連続性が損なわれ、思考が中断されてしまう問題を解決したい。

### 3.3 目的

* 同一ウィンドウ内でPDFを読みながらノートを取れる環境を提供し、往復コストをゼロにする
* 読んだ本を、自分自身の理解に基づいた「一つの知識ファイル」としてアーカイブできるようにする
* 断片的で後から見返しても意味が分からないメモではなく、文章として書かれた深い学習ノートを促す設計にする

### 3.4 成功条件

以下の3条件をすべて満たした時点で、本プロジェクトは成功したと判断する(詳細は12章参照)。

1. 機能的完了条件: 機能要件のうちMustに位置づけた項目(F-01, F-02, F-03, F-05)がすべて実装され、正常に動作していること
2. 受け入れシナリオ(ドッグフーディング)の達成: 開発者自身が実際の技術書・語学教材を1冊、本アプリのみで最初から最後まで読了できること
3. 品質基準の達成: 上記読了プロセス中に、クラッシュおよびデータ損失が発生しないこと

## 5. 用語定義 {: #glossary }

| 用語         | 定義                                                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------------------------------------- |
| 没入型ノート体験   | ドラッグ&ドロップ的な断片操作ではなく、実際に紙のノートに書き込むような感覚で文章を書けるノート機能                                                                          |
| AIルックアップ   | 読書中に出会った未知の単語・専門用語・語源などについて、ウィンドウを離れずに即座に質問できるAI検索機能。テキストを選択(クリック・ドラッグ)することでトリガーする方式とする。NotebookLM的なチャット型AIとは異なり、天気などの無関係な質問には応答しない設計 |
| 個人辞書       | ユーザーがアーカイブした単語を蓄積していく、内蔵の辞書機能。本を横断して1つに統合される(9章N-06参照)                                                                        |
| 一つの知識ファイル  | 読んだ本ごとに作成される、注釈・ノート・辞書登録単語が統合されたアーカイブ                                                                                        |
| 電子データPDF   | テキストがピクセル画像ではなく文字データとして埋め込まれているPDF(Word/LaTeX/電子書籍生成ツール等から出力されたもの)。本アプリの対応対象はこれに限定する                                               |

## 6. 機能要件 {: #functional-requirements }

| No.                         | 機能名       | 概要                                                              | 優先度                    |
| --------------------------- | --------- | --------------------------------------------------------------- | ---------------------- |
| <span id="F-01"></span>F-01 | PDF描画・書き込み | PDF上に自由に描画・書き込みができる                                             | 必須                      |
| <span id="F-02"></span>F-02 | 統合ノート機能   | 同一ウィンドウ内でノートを取れる。断片的なメモではなく文章での記述を基本とする                          | 必須                      |
| <span id="F-03"></span>F-03 | テキストブックマーク | PDF内のテキストをブックマークし、後で対応するノートへシームレスに飛べる                             | 必須                      |
| <span id="F-04"></span>F-04 | AIルックアップ  | テキスト選択(クリック/ドラッグ)をトリガーとし、単語・専門用語・語源等に関する質問にスコープを限定したAI検索          | 推奨(リリース前の最終実装項目)      |
| <span id="F-05"></span>F-05 | 個人辞書      | 語学学習者向けに、単語をアーカイブできる内蔵辞書機能。本を横断した共有ストアとし、以前読んだ本で出会った単語を思い出せるようにする | 必須                      |

### 6.1 F-01 PDF描画・書き込み

**目的**

PDF本文に直接描き込むことで、紙の本に近い没入感のある読書体験を提供するため。

**入力**

ユーザーによるポインタ(ペン/マウス)操作、電子データPDFファイル

**処理**

PDF描画レイヤー上へのストローク記録・保存

**出力**

PDF上に重畳表示される注釈データ

**制約・例外**

* 電子データPDF(テキストレイヤー付き)のみ対応
* スキャン画像ベースのPDFは対象外(11章参照)

### 6.2 F-02 統合ノート機能

**目的**

ウィンドウ切り替えなしに、読書と同じ画面内で文章としての学習ノートを記述できるようにするため。

**入力**

ユーザーによるテキスト入力

**処理**

ノート内容の保存、対応する本・ブックマークとの紐付け

**出力**

本ごとに蓄積される文章ノート

**制約・例外**

* 断片的なメモではなく、文章として書かれた深い学習ノートを促す設計とする

### 6.3 F-03 テキストブックマーク

**目的**

PDF内の特定テキストと、それに対応するノートをシームレスに往復できるようにするため。

**入力**

PDF内でのテキスト選択操作

**処理**

選択箇所の位置情報を記録し、ノートへのリンクを生成

**出力**

ブックマーク一覧、対応ノートへのジャンプ機能

**制約・例外**

* なし

### 6.4 F-04 AIルックアップ

**目的**

読書中に出会った未知語・専門用語・語源について、ウィンドウを離れず即座に調べられるようにするため。

**入力**

テキスト選択(クリック・ドラッグ)によるトリガー

**処理**

選択テキストを対象に、語彙・専門用語・語源に関する質問へスコープを限定したAI検索を実行する。既存オープンモデルのファインチューニング/プロンプト制約によって実現する。

**出力**

質問に対するAI回答

**制約・例外**

* NotebookLM的な自由対話型AIとは異なり、天気などスコープ外の質問には応答しない
* 推奨要件であり、リリース前の最終実装項目と位置づける(未実装のままv1をリリースした場合、実装完了後にv1.1として扱う)

### 6.5 F-05 個人辞書

**目的**

以前読んだ本で出会った単語を、人間の記憶のように本を横断して自然に思い出せるようにするため。

**入力**

ユーザーによる単語のアーカイブ操作

**処理**

単語データを、本を横断した共有ストアへ保存する。由来となった本・ブックマークへの参照を保持する。

**出力**

蓄積された個人辞書一覧

**制約・例外**

* 個人辞書は本ごとではなく、全書籍横断の共有ファイルとする(9章N-06参照)

| システム            | 用途                     | 通信方式                       |

デスクトップGUI画面、SQLiteファイルへの永続化出力。

## 11. スコープ外

本バージョンでは以下を対象外とする。

* モバイルアプリ版
* Webブラウザ版
* NotebookLM的なチャット型AI(自由対話型の要約・QA機能)
* 図表(グラフ・マインドマップ等)のみに依存したノート機能
* ビジネス化・収益化
* OCR対応・スキャンされた画像ベースPDFへの対応(理由:従来型OCRは精度・堅牢性の面で脆弱であり、より高精度なAI-OCRは訓練コスト・学習データ確保の面で個人開発の範囲を超えること。また公開時の最初のターゲットである英語・日本語コミュニティのうち、縦書きを含む日本語書籍は英語よりOCR精度がさらに低くなり、言語間で対応品質に不公平が生じること。対応対象は電子データPDF(テキストレイヤー付き)に限定する)

## 12. 完了基準 {: #acceptance-criteria }

本バージョンは以下を満たした時点で完成とする。

* [ ] 機能要件(6章)のうちMustに位置づけた項目(F-01, F-02, F-03, F-05)がすべて実装され、正常に動作している(F-04は推奨要件のため必須条件には含めない)
* [ ] 開発者自身が、実際の技術書または語学教材を1冊選び、最初のページから最後のページまで本アプリのみを使って読了できる(受け入れシナリオ/ドッグフーディング)
* [ ] 上記読了プロセス中に、PDF上への描画・書き込み(F-01)、文章としてのノート記述(F-02)、テキストブックマークからノートへの遷移(F-03)、個人辞書への単語アーカイブ(F-05)を実際に使用し、複数ウィンドウの行き来を発生させずに1冊分の学習ノートを完成できる
* [ ] 上記読了プロセス中に、クラッシュおよびデータ損失(注釈・ノート・辞書データの消失や破損)が発生しない
* [ ] ドキュメントが実装と一致している
