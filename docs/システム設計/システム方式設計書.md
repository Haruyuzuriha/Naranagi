# システム方式設計書

**プロジェクト名**: PDF Viewer(仮称)
**作成日**: 2026-09-15
**ステータス**: ドラフト

---

## 1. システム概要

### 1.1 目的
語学学習者が電子書籍(PDF)を読みながら、同一ウィンドウ内で自由に描画・書き込みができ、
既知の単語や参照をシームレスにノートへ紐付けられる、没入型の読書・ノートアプリケーションを提供する。

### 1.2 対象ユーザー
語学学習者を主対象とする。

### 1.3 スコープ
- 対象: PDFへの自由描画・書き込み、テキストブックマーク機能、AI語彙検索、個人辞書機能
- 対象外: スキャン書籍へのOCR対応、モバイル版、Webブラウザ版

---

## 2. 要件の分類

システム方式設計では、システム要件定義で定めた要件を「ハードウェアで実現するもの」
「ソフトウェアで実現するもの」「手作業で実現するもの」の3つに分類する。
手作業に分類された要件はシステムには搭載しない。

| 要件 | 分類 | 備考 |
|---|---|---|
| PDF表示・描画・書き込み | ソフトウェア | 本システムの中核機能 |
| 注釈・ノート・ブックマークの永続化 | ソフトウェア | SQLiteによるデータ管理 |
| AI語彙検索 | ソフトウェア | オンライン時のみ動作 |
| 個人辞書アーカイブ | ソフトウェア | 横断共有DB |
| PC本体・ストレージ等の実行環境 | ハードウェア | ユーザー所有のPCに依存(本システムでは設計対象外) |
| スキャン書籍のOCR前処理 | 手作業 | 対応見送りのため、ユーザー自身が別途対応する前提。システムには搭載しない |

→ 「ソフトウェアで実現するもの」に分類された要件を、次工程(ソフトウェア要件定義)で具体化する。

## 3. システム構成

### 3.1 コンポーネント構成

本システムは、以下4つの機能モジュールが**共通の基盤モデルを共有し連携動作**する構成とする
(バラバラな機能の寄せ集めにはしない)。

| モジュール | 役割 |
|---|---|
| UI層 | PDF表示、描画・書き込みインターフェース |
| 注釈エンジン | 描画・書き込み・テキストブックマークの管理、ノートとの紐付け |
| AIルックアップエンジン | 単語・専門用語・語源などに範囲を限定した即時AI検索 |
| 辞書エンジン | 学習者が単語をアーカイブできる個人辞書機能 |
| データ永続化層 | SQLiteによるデータ管理(3.3節参照) |

### 3.2 プラットフォーム構成
PC専用デスクトップアプリケーションとする。モバイル・Web版は非対応。

### 3.3 データ方式(ハイブリッド構成)
- **本ごとのSQLiteファイル**: 注釈・ノート・ブックマークを本単位で独立管理(「一つの知識ファイル」思想に対応)
- **横断共有SQLiteファイル**: 個人辞書は全書籍を横断した1つの共有ファイルとする
  (人間の記憶と同様、「以前どこかで読んだ単語」を自然に思い出せる設計とするため)

## 4. 使用技術

| 項目 | 内容 |
|---|---|
| 実装言語 | Java(全面採用。Enterpriseに限定されないことを実証する目的も兼ねる) |
| データベース | SQLite |
| AI方式 | 既存オープンモデルをファインチューニング/プロンプト制約(ゼロからの訓練は非採用) |

---

## 5. 非機能要件

### 5.1 オフライン動作
AI機能を除く大半の機能は、オフライン(Wi-Fiなし)環境でも動作すること。

### 5.2 開発体制
一人開発によるオープンソースプロジェクトとする。商用化は目的としない。

### 5.3 品質方針
実装速度よりも正しさを優先する。低品質なコードや「バイブコーディング」は避ける。

---

## 6. 制約・前提条件
- スキャン書籍のOCR対応は見送る(AI-OCR訓練コストの高さ、英語話者優遇の公平性問題、日本語縦書きの精度問題を理由とする)
- AI機能の実装はリリース前の最終工程として位置づける
- AIルックアップの対象は「単語・専門用語・語源など」に限定し、無関係なプロンプト(天気など)は受け付けない
